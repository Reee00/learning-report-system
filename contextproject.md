# Learning Report System - Current Project Context

Status audit: 2026-09-03. Updated: 2026-09-24 after the School Workspace + DIGISchool bulk schedule + shared-UI refactor (see "School Workspace, DIGISchool Bulk Schedule & Shared UI 2026-09-24"). Earlier updates: 2026-09-11 meeting-requirements (items A-G) and UX/security audit, 2026-09-13 attendance UX. Root codebase is the source of truth. Statements about runtime values that are not present in the repository are marked `Need Verification`.

## Project Overview
LRS is a Laravel web application for managing schools, classes, programs, students, attendance, coach reports, report review, and report media.

## Current Tech Stack
- PHP `^8.4`; Laravel `^12.0`; PHPUnit `^11.5.3`.
- Blade, Bootstrap 5.3 and Bootstrap Icons via CDN, with Vite/package scripts present.
- MySQL is the intended production database. Repository config supports MySQL and other Laravel drivers and defaults to SQLite when `DB_CONNECTION` is absent. Active environment value: `Need Verification` because `.env` is not in the repository.
- FastExcel handles student import. Attendance export supports CSV and PDF. Dompdf handles PDF generation.
- Cloudinary dependency/config/helper remain for legacy compatibility, but new report media is written through local Laravel storage.

## Architecture
Standard Laravel MVC with Blade views, Eloquent models, middleware, and service classes. `AuthorizationService` centralizes role capabilities and class/school access checks. `AttendanceScopeService` centralizes attendance/report filtering. `MediaStorageService` abstracts report media storage. There is no separate API application or `routes/api.php`.

Main tables are `users`, `schools`, `classes`, `students`, `coach_classes`, `reports`, `report_attendances`, `report_media`, `programs`, `program_classes`, `school_user`, `teaching_schedules`, `teaching_schedule_templates` (+ coach pivots), Laravel sessions, and Laravel notifications. The initial user migration contains legacy role values, then a later migration changes `admin` to `relation` and expands runtime roles. ## UX & Security Audit 2026-09-11
Implemented from the manual/USER audit, all verified by tests (191 passed):

- **P0 Download report**: print view `admin/reports/download.blade.php` renders photos AND attendance media inline via the authorized `/media/{media}` URL (cookie-authenticated in the browser print dialog). Videos render as a poster placeholder + original filename reference (a video cannot play inside PDF/print). Empty-media state shown. The "Kembali" button is server-computed context (`backTo`: pic → pic.dashboard, coach → coach.reports.index, admin → admin.reports.index) instead of blind history.back().
- **P1 Relation assign coach**: Relation gains `coaches.view/assign/reassign` capabilities and re-uses the existing SPV Coach workflow (`CoachController::assign/unassign` + `coach_classes`) — no parallel assignment system; SPV behavior unchanged.
- **P1 Custom notification composer**: `Admin\NotificationController` + `CustomNotificationService` (`notifications.send` capability: Relation global, school_pic scoped). Type: schedule / reminder / operational; multi-coach targeting; optional related schedule/report resolves an action URL. Cross-school or out-of-scope targets are rejected server-side (ValidationException). Coaches see unread banners on their report list and mark them read via the ownership-checked `coach.notifications.read` route. No Telegram/PWA.
- **P1 Schedule roster**: the schedule form fetches the master `students` of the chosen class (`GET admin/schedules/class-students/{class}`, `schedules.manage`, school-scope enforced), shows the roster, auto-fills `student_count`, and links to master-data management. No duplicate student records are ever created by the schedule module.
- **P2 Attendance UX** (revised 2026-09-13): `/attendance` is grouped by session date only (full-width accordion; 15 dates/page) with per-class student detail rendered server-side. Student accumulation is NOT shown on the index page — the former right panel and `GET /attendance/summary` route/controller were removed. Accumulation (`TOTAL HADIR` = count of `Hadir` statuses per student from the same scoped dataset; matrix keys are unique per student+date so duplicates cannot double-count) lives only in the downloadable documents: final CSV column `TOTAL HADIR` and a bold rightmost PDF column, both respecting active school/class/date filters and the requester's scope. PDF keeps A4 landscape, school → class separation, and page breaks.
- **P2 Report list UX**: `admin.reports.index` groups the paginated, already-scoped collection into a School → Class accordion (server-side grouping only — no scope bypass via query manipulation).
- **P3 Login hardening**: rate limiting keyed `email|ip` (5 attempts, progressive decay) via `RateLimiter`; generic identical error for wrong-email and wrong-password (anti-enumeration); `session()->regenerate()` on login success; logout invalidates + regenerates token; session config verified (http_only, same_site=lax, secure via env).
- **P3 Activity log**: `activity_logs` table + `ActivityLogService` (single write path; metadata scrubbed of password/token/secret keys), SuperAdmin-only console (`/admin/activity-logs`, filter user/role/action/date/keyword + detail view, `users.manage` route gate + `isSuperAdmin()` controller check), wired into login/logout/login-failed, user CRUD + password reset, school/class/program/student CUD + import, report submit/resubmit/approve/reject, reminder sending (Relation + PIC), custom notification sending, schedule CRUD + import, coach assign/unassign. Retention: `activity-logs:purge --days=7` scheduled daily at 02:17.


Login/logout are handled by `LoginController` and Laravel session authentication. Routes use `auth`, `role`, `permission`, or `permission_any` middleware. `AuthorizationService` grants SuperAdmin wildcard capability and explicit capabilities to other roles. Backend checks also enforce school/class scope; UI visibility is not the security boundary.

## Roles & Permissions
Authentication (`LoginController`): session-based login with rate limiting keyed `email|ip` (5 attempts, progressive decay), generic identical error for wrong-email and wrong-password (anti-enumeration), and session ID regeneration on success; logout invalidates and regenerates the token. Runtime roles are exactly:
- `superadmin` / SuperAdmin: wildcard capability and global access; exclusive access to the activity-log console.
- `relation` / Relation: dashboard; school, class, program, student management; attendance view/export; report browse/review/download; report reminders (all coaches); schedule view/manage; custom notifications; coach assignment (re-uses the SPV Coach workflow, 2026-09-11).
- `spv_coach` / SPV Coach: dashboard, coach CRUD and assignment/reassignment; attendance view/export; report browse.
- `coach` / Coach: own reports create/view/update; students in assigned classes; `accident_notes.view` capability; view own teaching schedule. There is no separate accident-notes table.
- `school_pic` / PIC DK SCHOOL: plotted-school students/reports and approved attendance; attendance export; report reminders (only coaches teaching in plotted schools, primary or additional); schedule view + manage (plotted schools only, enforced server-side); custom notifications to plotted-school coaches only.
- `teacher_school` / TEACHER SCHOOL: plotted-school approved-report browse (status filter forced to approved server-side) and approved attendance/export. Status tabs (Ditolak/Perlu Diperbaiki/Disetujui) are hidden.
- `finance` / Finance: plotted-school approved attendance and CSV export only (no PDF — QA M-001).

`admin` and `PIC Sekolah` are not current runtime role names. The URL/controller namespace `admin/*` is a compatibility namespace used by Relation and other users according to capability.

## Business Logic
Relation and SuperAdmin manage operational master data. SPV Coach manages Coach accounts and class assignments. Coach access to classes is based on `coach_classes`. School-scoped users are assigned through `school_user`; legacy `users.school_id` is also included for compatibility. Scope is enforced in services/controllers.

## Master Data
Implemented entities and operations include School, SchoolClass, Program, ProgramClass, User/Coach, Student, and CoachClass assignment. Student import accepts XLSX, XLS, and CSV through FastExcel. Student template is streamed CSV. Since 2026-09-24 the school detail page is a workspace that assigns/creates/edits/removes classes and their programs in place (see "School Workspace, DIGISchool Bulk Schedule & Shared UI 2026-09-24"), reusing the same `SchoolClass` + `program_classes` master data; Master Program Kelas additionally shows where each class is used.

## Attendance
Coach submits student attendance as part of a report. Statuses are `present`, `absent`, `sick`, and `permission`. Attendance queries can filter school, class, date range, attendance status, and report status. The main page (`/attendance`, audit UX 2026-09-11) is grouped by session date — one accordion row per date with per-class student detail — and a per-student accumulation summary (total sessions, total present, percentage) loads through `GET /attendance/summary` respecting the active filters and the requester's scope. Relation, SuperAdmin and SPV Coach have operational-global scope. Coach sees own reports. PIC, TEACHER SCHOOL, and Finance see only plotted schools and approved reports. PIC, TEACHER SCHOOL, and Finance export according to their permissions; Finance has CSV export capability only.

MySQL ONLY_FULL_GROUP_BY (bugfix 2026-09-12): `AttendanceScopeService::query()` appends `ORDER BY report_attendances.id DESC`; the date-group query (`GROUP BY reports.report_date`) and the per-student summary (`GROUP BY students.id, students.name`) must call `reorder()` before their `groupBy`/`orderBy` — otherwise ORDER BY references a non-grouped non-aggregated column and MySQL (strict mode) rejects the query with error 1055. Final ordering is date DESC only (groups are unique per date) / student name only. Regression suite: `tests/Feature/AttendanceMysqlOnlyFullGroupByTest.php` — runs on a real MySQL connection (env `TEST_MYSQL_DATABASE` + optional `TEST_MYSQL_HOST/PORT/USERNAME/PASSWORD`; skips on the default sqlite suite), reproduces the old failing SQL, then verifies `/attendance`, `/attendance/summary`, filters, scope, pagination, and empty data.

## Coach Report
Statuses are `draft`, `submitted`, `approved`, and `rejected`. Workflow: Coach creates and submits -> Relation or SuperAdmin reviews -> approve or reject. Reject requires `admin_notes`; Coach may edit rejected/draft reports and submit again. Approval records `approved_by` and `approved_at`. SPV Coach can browse but cannot approve/reject.

Content fields (2026-09-11, req. F): `lesson_material`, `goals_materi` (goals pembelajaran pertemuan), and `activity_report` (progress/aktivitas siswa) — both required, max 2000 chars. The old single `activity_summary` textarea is replaced; legacy values were backfilled into `activity_report`. Update on edit re-validates class assignment (QA M-006). Create/edit forms carry client-side file size/count validation matching server rules (photos 10×10MB, videos 3×100MB, attendance 5×10MB) plus a graceful server-side `PostTooLargeException` handler.

## Report Reminder Notifications
`ReportReminderService` defines an incomplete report as a `teaching_schedules` session with `session_date <= today` lacking a matching report (same coach_id + class_id + report_date) with status `submitted`/`approved`. Relation/SuperAdmin can remind all overdue coaches (`reports.remind` capability, `POST /admin/reports/remind`); PIC School can remind only coaches teaching in plotted schools (`POST /pic/remind`). Notifications use the Laravel database channel (`ReportReminderNotification`); coaches see unread reminder banners on their report list and can mark them read. Deduplication (rule decided 2026-09-11): a coach who already has an UNREAD `ReportReminderNotification` is not sent a new one, regardless of sender (Relation or PIC); once the existing reminder is read, a later reminder may be created again.

## Teaching Schedule
`teaching_schedules` is a full management module (2026-09-11 refactor), not import-only. Columns: `school_id`, `class_id`, `program_id` (nullable), `coach_id` (primary coach — report ownership + reminder key), `session_date`, `day_of_week` (ISO 1=Mon..7=Sun, denormalized in a model `saving` hook so the day filter is portable MySQL/SQLite), `student_count`, `start_time`/`end_time` (always stored `HH:MM:SS` via model mutators), `tools_dk`, `tools_rk`, `jalan_minggu_ini` (bool, default true), `keterangan`, `topic`, `departure_location`, `departure_time`, `arrival_time`. Additional coaches live in the `teaching_schedule_coach` pivot (schedule_id, coach_id, unique pair); `additionalCoaches()` is the relation, `allCoaches()` merges primary + additional.

CRUD: `Admin\ScheduleController` — create/edit via shared form `admin/schedules/form.blade.php`, listing `admin/schedules/index.blade.php` dengan dua tab: **POLA per hari (default, §5)** dan **SESI tergenerate** (filter school, class, program, coach incl. additional, day, date range, start-time range). Sejak 2026-09-24, `create()` merender form pola mingguan `admin/schedules/bulk.blade.php` (lihat "Form pola jadwal DIGISchool"); aturan validasi level sesi tetap satu sumber lewat `scheduleRules()` + `buildScheduleAttributes()` yang juga dipakai `POST /admin/schedules/bulk`. Validation enforces: class belongs to school, primary + additional coaches are role `coach` AND assigned to the class via `coach_classes`, end_time > start_time, no duplicate session (school + class + date + start + end), no coach time conflict (same coach — primary or additional — with overlapping session same date). PIC School can manage schedules only in plotted schools (`schedules.manage` capability: Relation, SuperAdmin, school_pic); scope is applied inside the query so request filters cannot bypass it. Coach sees only schedules involving them (primary or additional). Reminder logic is unchanged: one report per session, owned by the primary coach; `senderCanRemindCoach` counts additional coaches for PIC scope.

Import (`TeachingScheduleImportService`, auto-detected format): (A) normalized template CSV/XLSX with columns `tanggal, nama_sekolah, nama_kelas, email_coach, jam_mulai, jam_selesai, topik` + optional `program, email_coach_tambahan (;-separated), jumlah_murid, tools_dk, tools_rk, jalan_minggu_ini, keterangan` — session-level import, unchanged; (B) the company master workbook ("Sistem Academic - CENTER & DIGISchool", READ-ONLY) — weekly DIGISchool sheets (SENIN–SABTU) detected by header signature (NAMA SEKOLAH + JAM KELAS + KELAS) via OpenSpout, merged-cell carry-down for school/program/departure/jam_kelas, unlabeled spare coach columns, continuation rows (no KELAS) append additional coaches. **Sejak refactor pola 2026-09-25 nama sheet = HARI dan kolom KET = tanggal mulai pola blok sekolah itu** (`parseKetStartDate` membaca "Mulai tanggal 3 Agustus 2026", "Mulai 3 Agustus 2026", "3 Agustus 2026", "3 Agustus" → tahun berjalan, `10/08/2026`, `2026-08-10`); tiap blok sekolah menjadi satu pola independen dengan `start_date` dari KET-nya dan `meeting_count` dari input `meetings` (default 20). Tidak ada lagi `week_start` — parameter itu diabaikan bila dikirim. Blok tanpa tanggal mulai valid DILEWATI dengan pesan yang menyebut sekolah + sheet (bukan dikarang tanggalnya), begitu pula blok yang tanggalnya tidak jatuh pada hari sheet-nya. Name normalization strips "sekolah" prefix, "kelas" word, honorifics (mr/bu/pak/kak/bang) and parenthesized remarks. All referenced schools/classes/programs/coaches must exist in LRS master data; unmapped rows are skipped with detailed errors. Import is idempotent: pola dengan (hari + sekolah + tanggal mulai) yang sama dikenali ulang, dan sesi per tanggal duplikat dilewati. Import/template requires `schedules.manage`.

## Pola Jadwal per HARI + SEKOLAH (refactor 2026-09-25)
Workbook operasional DIGISchool adalah **satu sheet per hari**, dan di dalam satu hari ada banyak sekolah yang masing-masing punya tanggal mulai sendiri di kolom KET. Karena itu **tidak ada periode/start-date global** — asumsi lama (`period_start`..`period_end` + `meetings_target` untuk seluruh workbook) sudah dibuang.

- **Pola** = kelompok baris `teaching_schedule_templates` dengan `(day_of_week, school_id, start_date)` yang sama — mis. "SENIN — Penabur GS, mulai 10 Agustus 2026, 20 pertemuan". Identitasnya `patternKey()`, filternya `scopePattern()`, pengelompokannya `groupIntoPatterns()`. **Tidak ada tabel pola baru** — model template/sesi yang ada diadaptasi, bukan digantikan.
- Kolom: `pattern_name`, `start_date` (anchor pertemuan ke-1 pola ini), `meeting_count` (default 20), `day_of_week` (ISO), plus payload sesi lengkap (school, class, program, coach, jam, student_count, tools, jalan_minggu_ini, keterangan, topic, departure). `teaching_schedule_template_coach` menyimpan coach tambahan. `end_date` adalah turunan (`start_date + meeting_count - 1 minggu`), bukan kolom. Index `tst_pattern_idx (day_of_week, school_id, start_date)`.
- Migrasi `2026_09_25_000001_school_day_schedule_patterns` me-rename `period_name→pattern_name`, `period_start→start_date`, `meetings_target→meeting_count`, membuang `period_end` (index lamanya dilepas dulu — SQLite menolak `DROP COLUMN` selama kolomnya masih terindeks), lalu mem-backfill `start_date` ke kemunculan hari pola pertama pada/atau setelah tanggal periode lama sehingga tanggal pertemuan ke-1 sama persis dengan hasil generate sebelumnya.
- `ScheduleTemplateService::generate()` membuat pertemuan ke-1..`meeting_count` dengan tanggal berulang mingguan mulai dari `start_date` pola itu (tidak ada batas `period_end`). Aman dipanggil ulang: tanggal yang sudah ada dilewati, jumlah sesi tidak pernah melebihi `meeting_count` meski ada sesi yang dipindah karena libur, dan `renumberSessions()` menjaga nomor pertemuan tetap 1..N tanpa bolong. Libur = hapus/pindah sesi individual di modul jadwal biasa.
- **§4 — status mingguan bukan definisi pola.** `jalan_minggu_ini` ("Jalan Minggu Ini?") adalah status OPERASIONAL pada baris pola dan pada sesi. Mengubahnya tidak menyentuh `start_date`/`meeting_count`, dan generate ulang setelahnya tidak menambah sesi (kapasitas dibatasi `meeting_count`), jadi pola berulang tidak pernah rusak karena perubahan status mingguan.
- Halaman jadwal utama (`GET /admin/schedules/index`) menampilkan **POLA per hari** sebagai daftar utama, default hari SENIN (§5), dengan tab `view=pola` (default) dan `view=sesi` (daftar pertemuan tergenerate dengan filter tanggal/jam). Detail satu pola + seluruh pertemuan tergenerate ada di `GET /admin/schedules/pattern?day=&school=&start=` (`admin/schedules/pattern.blade.php`). Daftar pola lintas hari: `GET /admin/schedules/templates` (`admin/schedules/templates.blade.php`, filter pill SEMUA/SENIN..SABTU).

## Media Storage
New files use `MediaStorageService` and the configured `filesystems.report_media_disk`, default `report_media`, rooted at `storage/app/report-media`. Files are outside the public symlink and served through authorized `/media/{media}`. MySQL stores `report_media` metadata/reference (`path`, type, original name, disk, file size), not binary media. Media types are `photo`, `video`, and `attendance` (bukti absensi, max 5 photos of 10MB — req. G; stored under `reports/{year}/{id}/attendance/`). Cloudinary support was fully removed on 2026-09-11: composer package, helper, config block, `media:migrate-cloudinary` command, and all external-URL fallback branches are gone (database held 0 external-URL rows at removal time); any legacy external URL appearing in a restored backup would now 404 gracefully.

Server upload limits (Add Video fix, 2026-09-11): Herd php84 `php.ini` sets `upload_max_filesize=101M`, `post_max_size=310M`, `memory_limit=256M` (backup `php.ini.bak-20260911`); `public/.user.ini` mirrors the limits for FPM deployments; nginx already allowed 128M+. `bootstrap/app.php` renders `PostTooLargeException` as a friendly flash error instead of a blank 500.

## Export
`/attendance/export` supports CSV and PDF. CSV is a school/class/student matrix with date columns plus the final `TOTAL HADIR` accumulation column (UX 2026-09-13). The matrix builder accumulates rows with `chunk(1000)` so the model collection is never fully materialized (QA M-003). PDF requires the full `attendance.export` capability — CSV-only roles (Finance) are refused server-side and see only the CSV button (QA M-001). Student import is separate from attendance export.

## UI/UX
The main Blade layout uses a left sidebar application layout, top bar, mobile drawer/overlay, Bootstrap grid, responsive tables, and CSS media queries. Shared UI components are centralized: pagination renders through one vendor view for every `->links()` caller, and table/badge wrapping rules live in the layout CSS rather than per page (2026-09-24). Responsive/mobile improvements are implemented, but the codebase does not establish PWA support or a claim of full responsive coverage. Finance, TEACHER SCHOOL, and Relation reuse shared views; there are no separate role-specific portals for each.

## Known Limitations
- Active `.env` and deployed database/storage values cannot be verified from the repository. `.env.example` now exists with placeholders; local `.env` contains real Cloudinary credentials and must never be committed (rotation of those credentials remains a user action — QA H-001).
- `classes(school_id, name)` has no database unique index. Duplicate class names inside one school are blocked by validation in `ClassController` and `SchoolController` (`LOWER(TRIM(name))` comparison), but pre-existing duplicate rows are neither detected nor merged. Adding the index requires a manual dedupe of production data first.
- "Assign kelas yang sudah ada" moves the class row (`classes.school_id`) rather than sharing it; the schema has no many-to-many school↔class relation, so a class belongs to exactly one school. Only classes with zero students, zero reports and zero teaching schedules can be moved — this keeps `reports.school_id` / `teaching_schedules.school_id` consistent with `classes.school_id`.
- Legacy Cloudinary compatibility was removed on 2026-09-11 (package, helper, config, command, external-URL fallbacks); a legacy external-URL row restored from an old backup would 404 on `/media/{media}` — verify backups before restoring old media data.
- No separate permissions/roles tables or Policy classes; permissions are code-defined.
- Reminder "overdue" detection depends on `teaching_schedules` being imported and current; without schedule data no coach is considered overdue.
- PHP upload limits were raised on the local Herd php84 ini (deployment is not Docker-based); any production PHP server must apply equivalent limits (`upload_max_filesize=101M`, `post_max_size=310M`, `memory_limit=256M`).
- No PWA claim and no separate Finance/Teacher UI.
